# 스캔 품질 확인

## 먼저 알아야 할 것

같은 도면을 두 번 넣어도 모델이 다르게 읽는다. **한 번 돌려 보고 좋아졌다/나빠졌다고
판단하면 틀린다.** 실제로 이 함정에 빠져, 결과를 나쁘게 만드는 변경을 좋아진 것으로
착각한 적이 있다.

## 돈이 들지 않는 검증부터

후처리(`scene/planRepair.ts`, `scene/resizeArea.ts`)는 순수 계산이라 API 없이 전부
확인된다. 여기서 먼저 막는다.

```bash
npx vitest run tests/plan-repair.test.ts tests/dimension-lines.test.ts
```

새 실패 사례를 만났으면 **고치기 전에** 그 모양을 시험으로 먼저 옮긴다. 실제 스캔에서
나온 값을 그대로 쓰고, 주석에 어떤 증상이었는지 적는다.

## 실제 호출이 꼭 필요할 때

프롬프트나 스키마를 바꿨으면 실제로 넣어 봐야 안다. 이때 지켜야 할 것.

- **사용자에게 먼저 알린다.** 유료 호출이다.
- 한 번만 돌린다. 여러 번 돌려 평균을 내지 않는다.
- 결과를 그대로 보여 주고 판단을 맡긴다.

임시 시험 파일은 `tests/*.tmp.test.ts`로 만들고 확인이 끝나면 지운다.

## 무엇을 보나

```
전체 크기      도면의 실제 치수와 견준다
실별 크기      치수선이 그어진 실은 그 값과 정확히 같아야 한다
겹침 건수      0이어야 한다
가구 규격      침대 1500×2000 같은 표준에서 벗어나지 않았는가
```

## 이 프로젝트가 정한 규칙

1. **치수선이 최우선.** 도면에 그어진 치수가 있으면 그 값이 답이다.
2. **치수선이 없으면 그림 그대로.** 지어내지 않는다. 실 안에 적힌 면적(24.1㎡ 같은
   글자)으로 치수를 추정하지 않는다 — 그 숫자는 벽 두께를 품기도 해서 같은 도면의
   치수선과 어긋난다.
3. **사용자가 고칠 수 있어야 한다.** 스캔이 틀렸을 때 답은 AI를 더 조이는 게 아니라
   평면도에서 실을 골라 치수를 직접 넣는 것이다 (`resize_room_area`).

이 순서를 바꾸려면 사용자에게 먼저 물어본다. 한 번 정한 규칙이다.
