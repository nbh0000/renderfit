# 이 저장소의 글쓰기

## 주석 — 무엇이 아니라 왜

코드를 다시 읽어 주는 주석은 쓰지 않는다. 대신 **왜 이렇게 됐는지**, 특히 어떤 문제를
겪고 이 모양이 됐는지를 남긴다. 그래야 다음 사람이 되돌리지 않는다.

나쁜 예:

```ts
// 캔버스 크기를 확인한다
if (canvas.clientWidth !== box.clientWidth) { ... }
```

좋은 예:

```ts
/*
 * 3D를 열면 캔버스가 300×150(기본값) 그대로 멈춰 있는 일이 있다. 그러면 아무것도
 * 그려지지 않아 회색 화면만 남는데, resize 이벤트가 한 번 오면 그제야 제 크기를
 * 잡는다. react-use-measure의 관찰자가 첫 측정을 놓치는 것이다.
 */
```

지켜야 할 것.

- **한국어로 쓴다.** 코드 식별자는 영어, 설명은 한국어다.
- 겪은 증상을 구체적인 숫자와 함께 적는다 — "3150mm짜리 침실이 2190mm으로 줄었다".
- 되돌리면 안 되는 이유를 밝힌다. 실패했던 다른 방법이 있으면 그것도 적는다.
- 한 줄이면 `//`, 사연이 있으면 `/* */` 여러 줄.
- 파일 첫머리에는 그 파일이 무엇을 맡는지 짧게 적는다.

## 문장

- 담백하게 쓴다. 감탄이나 과장은 넣지 않는다.
- 줄 길이는 100자 안쪽. 주변 파일에 맞춘다.
- 강조는 `★`를 앞에 붙인다 (프롬프트 안에서 특히).

## 사용자에게 보이는 문구

- 존댓말로 쓴다.
- 무엇이 잘못됐는지와 **다음에 뭘 하면 되는지**를 함께 준다.
  - 나쁨: "실행에 실패했습니다."
  - 좋음: "저장하지 못했습니다. 편집 내용은 화면에 그대로 있으니 잠시 후 다시 시도해 주세요."
- 겁주지 않는다. 사용자가 잘못한 게 아니면 사과를 요구하는 말투를 쓰지 않는다.

## 커밋 메시지

제목은 `타입: 무엇을 고쳤는지` 한 줄, 한국어. 본문에는 증상 → 원인 → 고친 방법을 적고,
실제로 확인한 결과를 숫자로 남긴다.

```
fix: 도면에서 읽은 가구가 방보다 크고 서로 겹치던 문제

아파트 평면도 한 장을 넣으면 2.45×2.52m 침실에 폭 2.4m 침대가 90도 돌아 누웠고,
식탁 의자 넷이 식탁과 같은 좌표에 쌓였다.

...

실제 도면으로 확인: 실 5개의 면적이 도면에 적힌 값과 일치하고, 가구 겹침 0건.
```

시도했다가 접은 방법이 있으면 그것도 적는다 — 다음 사람이 같은 길을 다시 파지 않는다.

## 테스트

`describe`·`it` 이름도 한국어로, 무엇을 보장하는지 문장으로 쓴다.
파일 첫머리 주석에 **어떤 실제 사고에서 나온 시험인지** 적는다.

```ts
/**
 * 도면 스캔 결과 다듬기.
 *
 * 아래 값들은 실제 아파트 평면도 한 장을 넣었을 때 나온 것과 같은 모양의 오류다 —
 * 2.45×2.52m 침실에 폭 2.4m 침대가 들어왔고, 식탁 의자 넷이 겹쳐 쌓여 있었다.
 */
```
